Association rules — support, confidence, lift

The one skill: mine "if A then B" rules and read the three metrics correctly.

By the end you can Compute and interpret support, confidence and lift, explain the Apriori property, run the mlxtend pipeline, and name the algorithm family. This is Part 1 of your research doc — the concepts behind what you already wrote.

The task — find co-occurrence

Association-rule learning finds "if A, then B" patterns in transaction data: rows are baskets, cells are which items they contain. No labels, no target — only which items appear together. Classic example: {bread, butter} → {milk}.

The three metrics

MetricFormulaReads as
Supportcount(A ∪ B) / total transactionsHow common the itemset is overall.
Confidencesupport(A ∪ B) / support(A)How often B is present when A is.
Liftconfidence(A→B) / support(B)How much more often than chance.
Reading lift. Lift > 1 = A and B co-occur more than chance (useful). = 1 = independent. < 1 = they avoid each other. Confidence can be high just because B is common — lift is what corrects for that.

The two-step recipe (and why Apriori is fast)

  1. Find frequent itemsets — those with support above min_support. This is the expensive part: the number of possible itemsets grows exponentially.
  2. Generate rules — keep those whose confidence (and lift) pass a threshold.

Apriori prunes step 1 using the Apriori property (downward closure):

Apriori property. If an itemset is infrequent, then every superset of it is also infrequent. So once {beer} is too rare, you can discard {beer, diapers} without ever counting it.

The algorithm family

  • Apriori — level-by-level candidate generation + pruning. Simple, but many passes over data.
  • FP-Growth — builds an FP-tree; no candidate generation; usually faster.
  • Eclat — vertical layout (item → list of transaction IDs); support by set intersection.
  • Maximal / closed itemsets — compact summaries; GSP / PrefixSpan — sequential order matters.

Python (mlxtend)

from mlxtend.preprocessing import TransactionEncoder
from mlxtend.frequent_patterns import apriori, association_rules
import pandas as pd

transactions = [['bread','butter','milk'], ['bread','milk'], ['beer','diapers']]
te = TransactionEncoder()
basket = pd.DataFrame(te.fit(transactions).transform(transactions),
                      columns=te.columns_)

freq = apriori(basket, min_support=0.01, use_colnames=True)
rules = association_rules(freq, metric="lift", min_threshold=1.0)
rules[['antecedents','consequents','support','confidence','lift']].head()

On the Online Retail data you'd build baskets per InvoiceNo (the invoice is the transaction, and Description is the item) — the same rows your notebook already cleaned.

Limitations. Rules show co-occurrence, not causation. Low support thresholds explode into thousands of trivial rules; high thresholds miss rare gems. Lift + domain sense are how you filter.
