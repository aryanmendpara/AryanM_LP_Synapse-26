K-Means & the elbow method

The one skill: explain K-Means in a paragraph, and pick k with confidence.

By the end you can Describe the assign-then-update loop, name exactly what K-Means minimises, use the elbow method to choose k, and know when K-Means is the wrong tool. Maps to your notebook's K-Means and elbow cells.

Where this sits

In Lesson 1 you reduced the customer data to data_pca. K-Means now runs on that reduced data to group customers. This is partitional clustering — every point gets exactly one cluster, no noise category (contrast DBSCAN).

The algorithm — four steps, repeated

  1. Choose k — how many clusters you want.
  2. Initialise — place k centroids (scikit-learn uses k-means++ by default, which spreads the initial centroids out).
  3. Assign — label every point with its nearest centroid.
  4. Update — move each centroid to the mean of the points assigned to it.

Repeat 3–4 until the assignments stop changing (convergence). Because a random start can land in a worse solution, scikit-learn runs the whole thing several times (n_init) and keeps the best — and random_state makes that repeatable.

The one-sentence version. K-Means repeatedly assigns points to the nearest of k centroids and re-centres those centroids on their points, until nothing moves.

What it's actually minimising: inertia

K-Means is minimising inertia (a.k.a. WCSS — within-cluster sum of squares): the total squared distance from each point to its own centroid.

inertia = 0
for each cluster c:
    for each point x in c:
        inertia += squared_distance(x, centroid_of_c)

In scikit-learn it's the inertia_ attribute after fitting. Lower is "tighter" clusters — but not a fair way to compare different values of k, because inertia always drops as k grows (more centroids = closer fits). That's precisely why the elbow method exists.

Choosing k — the elbow method

The elbow method plots inertia against k and looks for the bend: the point after which adding another cluster barely reduces inertia.

scores = []
for k in range(1, 11):
    km = KMeans(n_clusters=k, random_state=42)
    km.fit(data_pca)
    scores.append(km.inertia_)

plt.plot(range(1, 11), scores, marker='o')   # look for the bend
plt.xlabel('k'); plt.ylabel('Inertia'); plt.title('Elbow'); plt.show()

Your notebook uses Yellowbrick's KElbowVisualizer to draw the same curve. Either way, the elbow is a heuristic, not a law — read it together with silhouette (Lesson 4) before committing.

Fitting and reading the model

km = KMeans(n_clusters=3, random_state=42)
labels = km.fit_predict(data_pca)     # fit + return one label per row
km.cluster_centers_                    # (k, n_features) centroid coordinates
km.inertia_                            # the minimised WCSS
When K-Means is the wrong tool. It assumes clusters are round, similar-sized, and roughly equally dense. It breaks on rings/moons (use Spectral), varying density (use DBSCAN), and it lets outliers drag centroids around. You also must supply k.
