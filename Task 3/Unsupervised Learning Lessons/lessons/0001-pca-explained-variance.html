PCA & explained variance

The one skill: explain PCA in a paragraph, and choose how many components to keep.

By the end you can Say what PCA actually does, why you standardize first, and how to justify n_components=0.9 from the explained-variance plot. This fills the blank answer in your Task 3 notebook (the cell after the PCA reference links).

Why reduce dimensions at all?

Your customer dataset has many correlated features (balance, purchases, cash-advance, credit limit…). More features means: slower computation, harder visualisation, and the curse of dimensionality — in high dimensions, distances between points become so uniform that clustering degrades. PCA compresses the features while keeping most of the signal.

Where it sits in the Task 3 set: see the map. Note the order in the notebook — you reduce first, then cluster. That's deliberate.

What PCA does, mechanically

PCA finds new axes — principal components — by rotating the feature space so that:

  1. PC1 points along the direction of maximum variance in the data.
  2. PC2 points along the next-most-variance direction, perpendicular to PC1.
  3. …and so on. Each PC is a weighted blend of the original features.

Then you keep the first few PCs and drop the rest. You aren't deleting columns — you're building new columns that happen to capture the spread efficiently.

The one-sentence version. PCA re-describes your data using axes aligned with where it actually varies, so the first few axes carry most of the information.

Why you must standardize first

PCA maximises variance. Variance depends on units: a feature measured in thousands dwarfs one measured in single digits, so PCA would just follow the big-number feature. StandardScaler puts every feature on the same footing (mean 0, sd 1) so each one gets a fair say. Your notebook does this before pca.fit — that ordering is not optional.

Explained variance ratio — how many components to keep

Each PC captures a slice of the total variance. pca.explained_variance_ratio_ gives that slice as a fraction per component; the cumulative sum tells you how much of the original data a given number of PCs retains.

pca = PCA(n_components=0.9, random_state=20)   # keep enough PCs to reach 90% variance
pca.fit(scaled_df)                              # learn the axes
data_pca = pca.transform(scaled_df)            # project data onto them

pca.explained_variance_ratio_                   # e.g. [.30 .18 .12 ...]
np.cumsum(pca.explained_variance_ratio_)        # [.30 .48 .60 ...] -> crosses .90 at the cut

Setting n_components=0.9 tells scikit-learn: keep adding components until 90% of the variance is explained. That's why your transformed shape came out with 10 dimensions instead of the original feature count — the fit chose 10.

The trade-off to state in an exam. Lower n_components = faster, less visual clutter, but you lose information (the discarded variance). High = faithful but you may keep noise and no longer benefit. Explained variance is the dial you use to choose.
