Lesson 01 · Deep Learning

The artificial neuron & the perceptron

The one skill: build a single neuron and teach it to compute OR.

By the end you can Explain what a neuron computes (z = w·x + b, then an activation), write the perceptron learning rule from memory, and train one to solve OR — filling the first blank cell in Task_4A.ipynb (the PerceptronNetwork class).

Intuition first

Forget brains for a second. A neuron is a tiny decision-maker, and it decides the same way a bouncer at a door does.

Imagine a bouncer holding a short checklist. Each item on the list is a piece of evidence ("is wearing a wristband?", "is on the guest list?"). Not all evidence counts equally, so each item carries an importance score. The bouncer adds up the weighted evidence, adds a personal mood — how lenient they feel today — and if the total crosses a bar, the door opens. Otherwise it stays shut.

That's a neuron, exactly:

  • inputs → the evidence,
  • weights → how much each piece of evidence matters (can be negative — evidence against),
  • bias → the bouncer's baseline mood, independent of any evidence,
  • activation function → the rule that turns "total score" into a yes/no decision.

"Learning" is just the bouncer adjusting the importance scores after being told when they got a call wrong. Nothing more mystical than that.

So what exactly is a "perceptron"?

A perceptron is this neuron with one specific activation function: the step function — fire if the weighted sum crosses a threshold, otherwise don't. That is the entire definition: inputs, a weight per input, a bias (the threshold), and an output of 0 or 1. It is the simplest complete unit that can learn, and it's the thing you code in this lesson.

The word neuron is the general term (the same computation, but the activation may be smooth — sigmoid, ReLU — as in later lessons); perceptron is specifically the step-activated one. People use the two loosely, but in this workspace "perceptron" always means the step-activated single neuron, and "neuron" is the general idea.

Perceptron in one line. A perceptron = a single neuron whose activation is a step: ŷ = 1 if (w·x + b) ≥ 0 else 0.

So why "deep" learning?

In classical ML you hand-craft the features (you decide that "age" and "balance" matter). A neural network learns its own features by stacking neurons — early neurons spot simple patterns, later ones combine those into complex ones. On messy data (images, audio, text) that beats hand-crafted rules. The catch is the same as the perk: more layers to learn means more numbers to tune, and you need the machinery in this course to tune them (backprop, in Lesson 4).

The math, step by step

A neuron with two inputs does four things:

  1. Weighted sum. Multiply each input by its weight and add everything:
    z = w₁x₁ + w₂x₂ + … + wₙxₙ + b
  2. Write it as a dot product. That whole sum is just z = w·x + b. This is why NumPy matrices show up everywhere — a whole dataset of neurons is one matrix multiply.
  3. Activate. Push z through the activation function. For the perceptron that is the step function:
    ŷ = 1 if z ≥ 0 else 0
  4. Decide. ŷ is the output — fire (1) or don't (0).

The learning rule

After making a prediction ŷ for an example with true label y, compute the error and nudge every weight and the bias:

error = y − ŷ                    # true minus predicted
w ← w + η · error · x            # η = learning rate
b ← b + η · error

Read it as three cases, and it stops being scary:

  • Correct (error = 0): nothing changes. Training is self-stabilising once every point is right.
  • Missed a 1 (y=1, ŷ=0 → error=+1): add η·x to the weights, pushing z up so the neuron is more likely to fire next time.
  • Fired wrongly (y=0, ŷ=1 → error=−1): subtract η·x, pushing z down.
The one-sentence version. A neuron is a weighted sum plus a bias passed through an activation; the perceptron learns by nudging its weights toward every example it got wrong.

Worked example — OR with the weights given

Before training, just check one hand-picked guess: w = [1, 1], b = −0.5. For each OR row, compute z and threshold at 0:

x₁x₂z = x₁ + x₂ − 0.5ŷ (z ≥ 0)OR truth
00−0.500 ✓
010.511 ✓
100.511 ✓
111.511 ✓

So w=[1,1], b=−0.5 already solves OR. Training's job is to find such a setting starting from random weights.

The decision boundary

The line where z = 0 is the decision boundary — the (only) line that separates fires from non-fires:

x₁ + x₂ − 0.5 = 0, i.e. x₂ = 0.5 − x₁.

This one-line limit is the entire story of Lesson 3 (XOR). For now, just note: a single neuron can only ever draw a straight line.

The code, line by line

This is the first blank cell in Task_4A.ipynb. Here it is filled in:

import numpy as np

class PerceptronNetwork:
    def __init__(self, input_size):
        # one weight per input, plus one bias; small random starting values
        self.weights = np.random.rand(input_size)   # shape (input_size,)
        self.bias = np.random.rand(1)               # shape (1,)

    def predict(self, x):
        # the weighted sum plus bias, then the step activation
        weighted_sum = np.dot(x, self.weights) + self.bias
        return 1 if weighted_sum >= 0 else 0

    def train(self, X, y, learning_rate, epochs):
        for _ in range(epochs):
            for i in range(len(X)):
                prediction = self.predict(X[i])              # forward pass
                error = y[i] - prediction                    # true − predicted
                self.weights += learning_rate * error * X[i] # nudge weights
                self.bias += learning_rate * error           # nudge bias

What each line is doing:

LineMeaning
np.random.rand(input_size)Random numbers in [0, 1), one weight per input. A random start breaks symmetry — we'll see in Lesson 6 why zeros are fatal for bigger networks.
np.dot(x, self.weights)The dot product w·x. Requires x and weights to have the same length.
+ self.biasAdds the mood. Shape (1,) broadcasts against the scalar sum.
1 if weighted_sum >= 0 else 0The step activation. Note >=, so the boundary point itself counts as "fire".
error = y[i] - predictionTrue minus predicted — order matters (flip it and the neuron learns backwards).
self.weights += learning_rate * error * X[i]The rule: scale the input by error and η, then add. Zero error ⇒ zero change.
self.bias += learning_rate * errorSame idea, without an input to multiply by.

Now drive it — the OR truth table, and a training loop with a fixed seed so the numbers below are reproducible:

np.random.seed(0)                                 # reproducible random start
X = np.array([[0, 0], [0, 1], [1, 0], [1, 1]])    # OR inputs
y = np.array([0, 1, 1, 1])                        # OR outputs

perceptron = PerceptronNetwork(input_size=2)
perceptron.train(X, y, learning_rate=0.1, epochs=10)

for x in X:
    print(f"Input: {x}, Perceptron Prediction: {perceptron.predict(x)}")

print("weights:", perceptron.weights)
print("bias:", perceptron.bias)

Expected output:

Input: [0 0], Perceptron Prediction: 0
Input: [0 1], Perceptron Prediction: 1
Input: [1 0], Perceptron Prediction: 1
Input: [1 1], Perceptron Prediction: 1
weights: [0.5488135  0.71518937]
bias: [-0.09723662]
Read the output, don't just run it. The four predictions 0 1 1 1 are the OR truth table — the neuron learned OR. Notice the weights barely moved from their random start: the first example (0,0) predicted 0 correctly, and the positive starting weights were already enough for the other three, so most updates were toward a smaller bias. Your exact numbers will differ without np.random.seed(0), but the four predictions should not.

Common mistakes

  1. Flipping the error sign. error = prediction - y[i] makes the neuron learn the opposite of what you want. Always true minus predicted.
  2. Forgetting the bias. Drop it and the boundary is forced through the origin (w·x = 0), which can't solve AND — you'll see this in Exercise 1.
  3. Shape mismatch in the dot product. np.dot(x, self.weights) wants two vectors of equal length. Passing a column vector (n,1) instead of (n,) gives a matrix, not a scalar.
  4. Expecting identical results every run. The random weights change each time, so one run may solve OR in one epoch and another in five. Seed it if you want reproducibility.
  5. Learning rate too big or too small. 0.1 is fine here; 1.0 can oscillate forever, 1e-6 is glacial.
  6. Concluding "the perceptron is broken" from XOR. It isn't — XOR simply isn't linearly separable. That's Lesson 3, and the fix is hidden layers, not more epochs.

Recap — five bullets

  • A neuron computes a weighted sum plus a bias, then an activation: z = w·x + b, ŷ = step(z).
  • The perceptron learns by nudging weights toward every wrong example: w += η·(y − ŷ)·x, b += η·(y − ŷ).
  • Correct predictions give error = 0, so training automatically quietens down once all points are right.
  • A single neuron draws exactly one straight line; OR and AND are separable, XOR is not.
  • Random initialization means the run-to-run path differs — seed it when you need to compare outputs.

Practice (hints only — no solutions)

  2. Write the boundary. Using your trained weights and bias, write the equation of the decision line. Hint: set w₁x₁ + w₂x₂ + b = 0 and solve for x₂. There are many valid lines — any that separates the 0s from the 1s.
  3. Add an accuracy method. Write accuracy(self, X, y) that returns the fraction of correct predictions. Hint: loop over rows, count where predict(X[i]) == y[i], divide by len(X). Bonus: try it on XOR and watch it stall below 1.0.

Answer key

  1. A — the bias shifts the boundary (slope stays); it does not scale weights or store anything.
  2. B — error = y − ŷ = 0 whenever the prediction is already right.
  3. C — XOR is not linearly separable; no straight line splits its points.
  4. A — error = y − ŷ: true minus predicted.
  5. A — the random initial weights and bias change each run.
  6. B — z = 0 is a line in 2-D (a hyperplane in general).
  7. b ← b + η · (y − ŷ). No input term to multiply by, so it's just learning rate × error.
  8. Because a correct prediction gives error = 0, and every update is proportional to error, so all updates become zero.
  9. z = 1·1 + 1·0 + (−0.5) = 0.5. Since 0.5 ≥ 0, the output is 1.
  10. First predict: z = 0·1 + 0·1 − 0.5 = −0.5 < 0 → ŷ = 0, so error = 1 − 0 = 1. Then w ← [0,0] + 0.5·1·[1,1] = [0.5, 0.5] and b ← −0.5 + 0.5·1 = 0. New values: w = [0.5, 0.5], b = 0.
